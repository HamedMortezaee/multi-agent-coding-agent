# n8n Workflows

## 01-main-coding-agent.json

Import this file into the n8n instance running on n8nir.ir.

The workflow exposes one POST webhook:

```text
/webhook/eb5d4080-cb64-48d9-ba43-6f761425c1f4
```

The actual base URL is generated by your n8n instance.

## Workflow Configuration

The workflow no longer requires global n8n Variables.

After import, open the node:

```text
Workflow Config
```

and set:

```text
apiUrl = https://n8n-agent.samanooqazvin.com
apiKey = <same value as Security:ApiKey in CodingAgent.Api>
```

All HTTP Request nodes read these values from the `Workflow Config` node.

Set `apiKey` inside n8n before execution. The tracked workflow must keep secrets as placeholders.

## Start Request

```json
{
  "action": "start",
  "request": "Create a Todo ASP.NET Core Web API with CRUD operations.",
  "requestedBy": "hamed"
}
```

The response returns:

- executionId
- generated Plan
- status = WaitingForHuman
- sample review payload

## Human Approval

POST to the same webhook:

```json
{
  "action": "review",
  "executionId": "<execution-id>",
  "decision": "approve",
  "feedback": "Add Swagger documentation."
}
```

Allowed decisions:

```text
approve
modify
reject
```

### Modify

```json
{
  "action": "review",
  "executionId": "<execution-id>",
  "decision": "modify",
  "feedback": "Keep storage in memory and simplify the API."
}
```

The backend returns to Planning, the Planner uses the human feedback, and the workflow returns the revised Plan. Submit another review request afterward.

### Reject

Reject marks the run as Failed and the workflow stops before code generation.

## Real Execution

After approval the workflow performs:

```text
Generate Code
 ↓
Execute Project
 ↓
Review Result
 ↓
Is Fix Needed?
 ├── no  → Generate Final Report
 └── yes → Fix Project
              ↓
          Execute Project
              ↓
          Review Result
```

Execution is delegated by CodingAgent.Api to:

```text
https://n8n-runner.samanooqazvin.com
```

The Runner performs real:

```text
dotnet restore
dotnet build
dotnet test
```

A validated run completed with:

```text
3 tests passed
0 tests failed
Reviewer nextAction = complete
Status = Completed
```

## Why this workflow doesn't use the n8n Wait node

Human-in-the-loop is implemented as a durable state/resume pattern:

```text
start request
  ↓
backend status = WaitingForHuman
  ↓
workflow ends
  ↓
human review request
  ↓
same executionId continues
```

This keeps the human approval durable across n8n/ASP.NET Core restarts and avoids holding a hosted n8n execution open while waiting for a user.

The backend state machine still guarantees that Coder cannot execute before the Plan is approved.

## Final Report

After Reviewer completes, the workflow calls:

```text
POST /api/v1/runs/{executionId}/report
```

The backend builds a Markdown report containing:

- original user request
- approved plan
- human feedback
- generated project files and their contents
- execution attempts, stdout/stderr and execution status
- reviewer issues and next action
- final run status

The same report can also be retrieved with:

```text
GET /api/v1/runs/{executionId}/report
```

The final webhook response is intentionally compact and includes `status`, `codeGenerated`, `executionAvailable`, `executionSuccess`, `reviewSuccess`, `nextAction`, `summary`, and `reportMarkdown`.
